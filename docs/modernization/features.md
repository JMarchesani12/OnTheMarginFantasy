# Feature inventory

Source survey: 2026-10-28. Broad first pass, not a completeness or runtime claim. Stable IDs identify capabilities, independent of screen names. All evidence paths are repository-relative.

**Status:** apparently active = wired route, UI caller or operational entry point; uncertain = implementation exists but usage, deployment or reachability needs confirmation; potentially obsolete = explicit deprecation or an unregistered/unreferenced alternative. Absence from navigation alone does not establish obsolescence.

**Roles:** visitor, account holder, league member, commissioner, operator. These describe intended audiences from UI/logic, not verified enforcement. There is no global administrator role established by this survey. HTTP routes generally require Supabase JWTs; public exceptions are recorded below. REST actor IDs are often supplied by the client; their binding to JWT subjects remains unverified.

## Evidence shorthand

- `FE` = `front-end/src`; frontend routes are registered in `FE/App.tsx`.
- `UI(Name)` = `FE/screens/League/Name.tsx`; `C(Name)` = `FE/components/League/Name.tsx`.
- `API(area)` = `api/endpoints/area/routes.py`, `areaEndpoints.py`, `areaModel.py` in that directory (e.g. `api/endpoints/league/leagueEndpoints.py`). These files are the evidence for endpoint/table associations below; associations are identifiable, not exhaustive.
- Tables refer to `db/tables.sql` and `db/README.md`; names inferred only from comments are explicitly qualified.
- In endpoint paths, `L` = league ID, `M` = member ID, `R` = join-request ID, `T` = transaction ID, `W` = week ID, `N` = week number. Actual Flask parameter names/types are in the route files. Each method applies to the immediately following path(s).
