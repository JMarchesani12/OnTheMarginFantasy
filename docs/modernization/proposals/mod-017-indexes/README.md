# MOD017 index proposals — no rollout

Candidate package: one member-led ownership index. Selection evidence and limits are in [the report](../../mod-017-index-selection.md). No automatic migration or configured database execution is authorized by these files. Game and pending/history alternatives are excluded pending workload/plan evidence.

Tested PostgreSQL 17.6, ordinary public tables, `psql` with autocommit, no `--single-transaction`, transaction pooler, or enclosing BEGIN. An authorized operator must review a fresh target catalog, required owner/CREATE permissions, storage, traffic, lock budget and monitoring before any rollout. Use an application-approved statement/lock timeout; a failed concurrent build may leave an invalid index. Do not disable integrity or remove baseline indexes.

`preflight.sql` is read-only apart from session search_path. It refuses missing/wrong column types, nonordinary relations, invalid/not-ready indexes on the selected table, same-name drift and unsupported PostgreSQL majors. It inspects complete key expressions/direction, includes, predicate, method, uniqueness and constraint backing. Equivalent valid shapes under any name—including constraint-backed equivalents—mean skip/review. No name-only IF NOT EXISTS.

After approval, `\ir create.sql` in a supervised psql session checks the selected candidate before creation. Catalog changes between preflight and DDL are still possible: do not run competing DDL. Any race/failure requires a fresh inspection, never blind retry. Save the transcript and successful creation receipts; `\ir verify.sql` checks valid equivalent definitions. Run current canonical query output/EXPLAIN controls on the authorized target separately; local fixtures do not establish target latency or acceptance.

Recovery: review each newly-created receipt against the saved before/after catalog. In that same session only, `\set mod017_recovery_approved true` then `\ir recovery.sql` removes only exact OID/name/definition/nonconstraint identities successfully created by this package. Existing equivalents receive no receipt and cannot be removed. No CASCADE. If creation was interrupted before a receipt, this script refuses to infer ownership: preserve the invalid catalog row and obtain a separate operator-reviewed recovery using proof of prior absence and exact new OID/definition. Never assign an existing baseline index a fabricated receipt. Reconnecting or losing proof requires manual review; automatic recovery is intentionally unavailable.
