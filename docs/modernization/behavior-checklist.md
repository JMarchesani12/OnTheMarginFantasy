# Behavior preservation checklist

Source baseline: 2026-10-28. Read alongside [features.md](features.md) for routes, roles, tables and evidence paths, and [architecture.md](architecture.md) for startup/configuration. This is a source-derived checklist, not evidence that the deployed application works. No tests, application processes, jobs or database operations were run.

## Evidence and interpretation

- **C**: demonstrated by an implementation branch; preserve its supported behavior subject to the bug exclusions below. Runtime integration is unverified.
- **T**: asserted by an existing automated test; tests were inspected, not run. A mocked model/handler test does not demonstrate production authorization or a complete journey.
- **I**: inferred intended behavior or a proposed verification scenario; not an established requirement.
- **B**: known code limitation or suspected bug; record/reproduce separately, **do not preserve as a requirement**.
- **Q**: product decision needed; no requirement is assumed until answered.

Unchecked boxes are future verification work, not failed tests. Roles in the inventory describe intent; a hidden button is not evidence of API authorization. “No coverage found” means no corresponding test in the inspected repository suites, not proof that external coverage does not exist.

Evidence shorthand from the inventory applies: FE = `front-end/src`, UI = `FE/screens/League`, C(component) = `FE/components/League`, API(area) = its route/endpoint/model files under `api/endpoints/area`. Contract IDs below identify exact handler behavior or explicitly labeled frontend type expectations. Unspecified error statuses/shapes remain unknown; do not assume all failures return JSON.

## Shared checks inherited by every feature row

**P — permissions/data:** C protected HTTP requests pass bearer validation; exceptions are health, sports, search and user-by-UUID, plus separately authenticated sockets and OPTIONS. I for every account/league-scoped operation test anonymous, expired token, second account, nonmember, member and commissioner where applicable, including supplied IDs from a different account/league. Intended isolation is an audit target, not a claim of enforcement. Public-field exposure is Q1. Backend/CLI operations have operator access intent only; no app-level CLI permission system found.

**S — states:** preserve the specific loading/empty/error/submission branches cited below. Do not convert a failed request into a successful empty result by assumption. I test slow responses, rejected requests and repeated clicks. Where a state is not identified it is **unestablished**, not an implied spinner, retry button or success toast. CLI features have progress/empty/error/exit behavior instead of UI submission states.

**N — navigation/refresh:** C router Suspense provides “Loading…” during screen loading. C session is persisted; ordinary form state is generally component state unless explicitly stored. I compare in-app navigation, back/forward, cold URL and reload after a successful write. Do not invent unsaved-form persistence. Data reload and selection restoration are described per row; untested browser-history behavior is not guaranteed. B3/B4 are excluded limitations.

**A — asynchronous/integration:** preserve identified SDK/socket/job contracts, not an invented delivery SLA. For rows without an integration, no independent background behavior was found; their API data may still be changed by shared jobs. No evidence establishes realtime updates on every scoreboard or transaction panel.

## Important contracts — implementation versus consumer expectations

Fields below are important subsets, not closed schemas. Keep numeric IDs distinct: auth UUID, User.id, LeagueMember.id, SportTeam.id, SportConference.id and Week.id versus weekNumber. Dates cross JSON as strings; TypeScript annotations such as `Date` do not prove parsing. Optional/null fields are material, especially current week, state, owner and team names. Frontend casts do not validate a server response.
