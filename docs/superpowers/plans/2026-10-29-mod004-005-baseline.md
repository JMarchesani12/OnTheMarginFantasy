# MOD-004/005 local baseline implementation plan

> Execute inline in the existing audit checkout as continuation of the authorized modernization work. No deployed writes, merges or dependency installation.

**Goal:** Turn the assessed public schema into a checksummed local initialization/adoption baseline, and prepare independently tested browser-grant hardening/recovery SQL for review.

**Spec:** docs/modernization/backlog.md MOD-004/005; docs/modernization/mod-004-access-review.md and mod-005-schema-provenance.md.

**Architecture:** Preserve the observed schema/access behavior in a versioned baseline. A connection-aware Python module validates checksums, prerequisites and normalized state, then initializes an empty application schema or records adoption of an exact matching schema in one transaction. Its command-line entry point accepts only the marked local assessment server. Privilege tightening is a separate unapplied SQL proposal, tested and recoverable locally.

**Constraints:** No reconstruction of missing migration; synthetic Auth never becomes production DDL; preserve backend/job role contracts; no automatic production adoption/hardening. Existing schema state must be verified before a ledger entry is written. Edited historical files or conflicting ledger state reject rather than silently rebaseline. Tests never load .env.
