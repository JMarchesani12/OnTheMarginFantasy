# Team aliases and typo-tolerant search

> Superseded storage decision: the user subsequently approved database-owned aliases. See `docs/superpowers/specs/2026-11-19-school-alias-database-design.md` and its implementation plan. JSON remains offline seed/test data only; the frontend bundled copy was removed.
User approved both aliases and typo tolerance across draft and general team search. Keep database/display names and team identity unchanged. Exact names and aliases rank above prefixes, substrings, and word matches. Typo suggestions are a fallback when no strong match exists within the current filters. Never autocorrect or auto-select a team. Ambiguous abbreviations may return multiple teams; no guessed identity.

Use one versioned alias catalog seeded from ESPN's public team metadata (location, displayName, shortDisplayName, abbreviation), grouped by provider team identity across sports. Ship the backend catalog with api; a generated frontend copy allows independent deployment roots. A parity check ensures they match. Additional vetted aliases can be added without changing database names. Recognize complete school names and known mascot variants; arbitrary school-name prefixes never confer aliases. Institutional variants (University of X, X University) work without globally replacing ambiguous St with State; support Saint and State alternatives.

Implement equivalent deterministic matchers in Python and TypeScript, with shared behavioral fixtures to prevent drift. Normalize punctuation, ampersands, case, diacritics, and spacing. Allow adjacent transposition/insertion/deletion/substitution conservatively on words of at least four letters; permit two edits only on long words. Short abbreviations never receive fuzzy matches. Limit query length/token count to bound edit-distance work. Maintain existing search limit, authorization, ownership, and league/sport restrictions.

Apply to backend team lookup and frontend draft, roster/free agents/trades, conference schedule, and daily scoreboard. Match each scoreboard team separately. Preserve conference/tier/date filters, and existing grouping. The UI explains names/abbreviations/typos and always displays canonical names. No live database migration or network requests during ordinary search.

Alternatives considered: aliases alone miss typos; fuzziness alone cannot infer UNI; database alias tables need a migration and enrichment of every roster/schedule payload. Selected a shared bundled catalog plus deterministic typo fallback to cover existing name-only APIs without changing contracts. School short-name enrichment and an alias editor are future extensions.
