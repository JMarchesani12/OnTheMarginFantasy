# MOD-016 — Preview-first maintenance and history safeguards

## Approved approach and conservative write boundary

User chose safeguards first: preview/atomicity safeguards, refusal of calendar
changes for leagues with history, historical remapping and snapshots separate.
The existing rebuild script can cascade-delete linked transactions by deleting
weeks, and can commit score deletion before rescore fails. Neither is acceptable.

Selected approach: retain the shared calendar/scoring policies, replace ad hoc
maintenance orchestration with a focused service/repository, preview by default,
explicit --apply for eligible repairs, and one atomic transaction per league.
Alternative full historical period/ownership/transaction remapping requires a
separate policy/design and is intentionally deferred; merely wrapping the existing
destructive script in a transaction would not preserve historical meanings.

**Conservative implementation choice for approval:** only unused Pre-Draft leagues
may be written. Any draft picks, ownership intervals, transactions (any status),
weekly scores, completed/locked periods, active/completed draft state or finalized
season makes this tool preview-only. Do not silently permit historical rescoring
just because week boundaries happen to match. That would still change totals using
mutable game/tier/rule inputs without an agreed historical input policy. Existing
league lifecycle status alone is insufficient evidence of absence of history.
Unknown league/draft states fail closed. Draft order configuration alone (DraftTurn
and pre-state) is not ownership/scoring history and need not block unused repair.

This intentionally restricts the old destructive maintenance workflow. It does not
remove ordinary weekly completion or authorized standalone scoring contracts.
Future explicit historical rescore/remap/reopen workflows require separate design.

## Preview contract

Required --season-year; optional repeated --league-id. Default is preview, no
calendar, score, lock, ownership, transaction or finalization changes. Scope league
discovery by its actual seasonYear rather than scanning unrelated seasons; report
unknown/mismatched explicit IDs deliberately without acting on another league.
Require a matching SportSeason and a valid nonempty computed calendar.

One supplied read connection obtains actual league/season/settings and proposed
boundaries, existing Week IDs/numbers/dates/flags, history counts, draft state and
season-finalization state. Show periods kept/changed/added/removed with before/after
boundaries and IDs where present. Include affected ownership interval endpoints,
transaction links and score counts/totals as scoped aggregates/IDs; do not expose
private names, payloads or credentials. Mark whether a reference would be retained,
removed, or change temporal meaning; no automatic old-to-new mapping is asserted.
Football week zero and merged postseason periods follow the existing planner.

Historical fixtures must display the changed temporal meanings and the refusal
reasons. Applying a refused plan changes nothing: period IDs, ownership interval
endpoints, transaction references/status and stored score totals remain identical.
Preview does not write temporary scores or present speculative recomputed totals
as historical truth. Counts/totals are current before-state, not a new snapshot.

## Permitted apply and retry

--apply explicitly enables unused-league maintenance. Rebuild a fresh plan and
recheck all guards under locks; preview is informative, not a durable authorization
or immutable scoring snapshot. No force/ignore-history flag in this task.

Lock matching SportSeason, then the existing v1 ownership advisory mutex, then
DraftState/League/Week rows in the established draft-control order. Use season-before-ownership
ordering compatible with MOD-014. Recheck sport/year, status, finalized flag and
all history/reference/lock indicators after locking; stop on scope change. A pre-state
requires pick1 and null currentMemberId/expiresAt/lastPickAt. If no draft state was
locked but one appears while waiting for League, refuse without locking that new
row under League; retry may re-evaluate it from the correct order. Calendar
metadata planning must use the supplied transaction connection, not detached reads.

For an eligible league, preserve IDs for retained week numbers; add/remove only
unreferenced unused periods. No transaction or score deletion is permitted as a
shortcut: the history guard establishes these tables empty for the selected league.
Recheck references before removing obsolete weeks; never depend on ON DELETE CASCADE
as a repair mechanism. Preserve the existing rule-pinned calendar and score formulas.

Calendar edits, any score writes for ended periods, scoringComplete/current-next
period locks all share the same transaction and supplied connections. No independent
commit or provider/socket work inside it. Calculation, statement or deferred-commit
failure rolls back the whole league operation, including all earlier period changes
and scores. Retry recomputes/revalidates and can succeed after the cause is fixed;
other leagues continue. Committed success is durable; repeating --apply may refuse
because scores/locks now constitute history, rather than redoing historical work.

No historical tier, rule, conference, game or ownership snapshot is introduced.
Permitted unused repairs use current facts and the league's existing rule version;
this is explicitly not a guarantee of immutable results after future metadata edits.
No seasonFinalized reset, pending application, transaction retarget, ownership
renumber, historical row cleanup or durable migration ledger.

## CLI and compatibility

Keep configured engine loading lazy and support an injected engine for actual CLI
composition tests outside Flask. Return/print structured safe preview/applied/
blocked/failed outcomes. Nonzero exit for invalid explicit scope, blocked apply,
planning/execution failures; preview of a historically blocked league is a useful
report, not an attempted write. Sanitize acquisition/discovery/commit/startup errors
without raw SQL/exception payloads. Update operational docs so the old command no
longer implies immediate destructive changes. Preserve _compute_week_boundaries
compatibility used by postseason tests, forwarding a connection only when supplied.
No HTTP change, new schema/dependency, configured tool/job/provider run or deployment.
Work in the existing audit checkout, leave changes uncommitted.

## Verification and completion scope

Failure-first isolated tests for preview invariance and actual CLI defaults, exact
scope, every history/active/finalized guard, changed/unchanged calendar cases, ID
preservation, no cascading reference loss, whole-league calendar/score/flag/commit
rollback and retry, per-league isolation and safe errors. Historical ownership/
transaction/postseason fixtures must retain identical intended totals/references
when refused and expose explicit before/after proposed temporal changes.

Owned marked PostgreSQL on frozen schema plus current guards proves real calendar
planning/scoring composition, foreign-key cascade refusal, statement/deferred commit
rollback, and maintenance races with weekly/draft/transaction/finalization writers;
rechecks observe committed history and refuse rather than destroy it. Rerun affected
calendar/scoring/startup/weekly/finalization regressions. Independent final review,
full backend/frontend/build/diff checks, source-hashed evidence, owned cleanup.
Completion means safeguards delivered; historical remapping/rescore input/snapshot
policy remains an explicit follow-up, not implicitly implemented by this MOD.
