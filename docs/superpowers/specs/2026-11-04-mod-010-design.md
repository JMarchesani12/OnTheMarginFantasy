# MOD-010 ownership concurrency

User authorized continuing Priority5 with MOD-010. Preserve half-open ownership
[acquiredWeek,droppedWeek), including week0, null/unbounded ends, empty same-week
intervals and valid adjacent/future history. No scheduler timing/veto changes,
interval remapping, auto-cleanup or generic idempotency framework.

## Selected boundary

One transaction-scoped advisory lock per league shared by live/manual/timeout
draft writers, free-agent pending submission/application and trade application.
Acquire before DraftState/Transaction row locks, avoiding League row lock inversion
against draft finalization. A transaction application first reads only its league
hint, acquires that league lock, then locks/rechecks the row and rejects a changed
league. Existing pending/type/replay guards remain authoritative. Trade proposal/
response/veto semantics remain unchanged; application owns final ownership checks.

Free-agent effective-week routing, swap limit/member checks and pending reservation
checks move to the caller's locked transaction, preserving standalone helper
interfaces via optional connection arguments. Application revalidates dropped
ownership, added availability and post-drop conference caps on that connection
before completing; conflicts restore slots and pending status. Draft and trade
checks likewise occur after their common lock. This serializes supported commands,
not arbitrary external writers or all membership/calendar administration.

Alternatives: League row locks risk inversion with existing draft state→League
finalization; independent team locks do not cover per-member caps and multi-team
trades without broader ordered-lock machinery. Selected coarse per-league advisory
lock keeps independent leagues concurrent and scope auditable.

## Schema guard

Aggregate preflight finds1059 slots,0 reversed/negative intervals,0 wrong member
league/sport,0 nonempty overlapping pairs,10 empty intervals and0 adjacent transfers
on configured target. Empty and adjacent intervals are explicitly valid. Prepare
CHECK(start>=0,end>=start), same-league member FK using MOD-008 parent key, and
nondeferrable GiST exclusion for same league/team and overlapping int8range('[)').
Standard PostgreSQL btree_gist is available but not installed on configured target;
reviewed migration enables it (no download/new infrastructure) and leaves it on
rollback to avoid breaking unrelated dependents. No cleanup/data repair.

Exclusion rejects any conflicting future open-ended insertion atomically rather
than truncating an existing future interval. Adjacent/end-exclusive transfers and
empty intervals remain valid. Pending reservations retain current requested-week
policy; final application validates actual ownership/caps. Queue overbooking
across different effective weeks is not silently redefined as an ownership change.

## Proof and rollout

Failing real PostgreSQL races before lock: free-agent submissions, manual/draft
and free-agent application, different pending trades and conference caps. Prove
observed waits, one valid owner, replay/no mutation and rollback; re-run prior
transaction/draft contracts. Baseline + all migrations verifies clean/dirty/replay,
exclusion/check/FK and empty/adjacent/future behavior. Independent review before
applying configured SQL with fresh aggregate checks and bounded timeouts. No real
jobs/draft/ownership commands or backend deployment during rollout.
