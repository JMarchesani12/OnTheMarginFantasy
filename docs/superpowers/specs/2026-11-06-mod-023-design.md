# MOD-023 — Committed draft notifications and reconnect convergence

## Intent and confirmed access policy

Publish missing committed draft transitions and make connected/reconnected clients
converge on current authorized state. User confirmed rechecking membership/session
validity before snapshot delivery and on every join/reconnect: removed members and
expired sessions cannot continue receiving new private draft data through stale
room membership. Preserve member-only draft scope; no commissioner exception without
membership. A delivery check governs new emission; already authorized/in-flight data
cannot be recalled.

## Recommended approach and alternatives

Keep existing PostgreSQL NOTIFY and Socket.IO transport/event shapes. Notifications
are wakeups, not a durable ordered event stream. Route all outbound draft snapshot
paths through one recipient authorization boundary. On the browser, rejoin on every
connect and coalesce all draft refresh triggers through one serialized authoritative
HTTP snapshot loader with lifecycle-generation cancellation.

A database revision/outbox and replay platform would add schema and delivery policy
beyond this bounded card; not selected. Comparing serverNow/updatedAt as a global
revision is unsafe: serverNow is a clock sample after multiple reads, not a committed
sequence, and some configuration changes have no DraftState row. Keep their existing
clock/display uses without treating timestamps as ordering guarantees.

## Commit-only publication

Inventory all mutating draft branches: live/manual/auto pick, start/pause/resume/order,
AUTO-SKIP rotation, last-turn clock extension, and direct/implicit finalization.
Add missing pg_notify calls on the caller's actual transaction connection. Notification
failure must roll back that transition; statement or deferred-commit rollback must
publish nothing to a real LISTEN subscriber. No-op/denied paths do not manufacture
transitions. Preserve existing channel and {leagueId,reason} payload shape/reasons;
newly covered transitions receive explicit internal reason strings.

Final picks and finalization may generate more than one wakeup, and existing HTTP
broadcast plus listener delivery may duplicate updates. Coalescing handles these;
there is no exactly-once delivery claim. Do not independently commit or send socket
messages inside a domain write transaction. HTTP broadcasts occur after successful
commit; trusted worker/job transitions reach the same committed notification path.

## Uniform authorization for joins and delivery

Both direct HTTP broadcasts and database-listener broadcasts use the same guarded
broadcaster. Enumerate actual current room participants; before each recipient emit,
validate the server-held authenticated session and current membership/principal.
Fail closed on expired/invalid session, deleted/missing/ambiguous identity, revoked
membership or authorization lookup failure. Evict/reject that subscription and emit
only a safe generic draft:error where appropriate; never send private snapshot/pick
payload to an unvalidated participant. Do not fall back to an unchecked room emit.

Socket connect/join uses existing Supabase verification and verified subject binding,
with explicit exp validity for draft sessions. Keep tokens only in server session
memory when needed for fresh verification, never notification payloads/logs/errors.
Join obtains the member-scoped snapshot capability used by HTTP, then rechecks access
at delivery. Failed joins must not leave an authorized room subscription behind.
Leave/disconnect can always clear the caller's own subscription, including after
revocation/expiry; do not require membership to let a socket leave its own room.
Validate league IDs through existing typed bounds and sanitize unexpected errors.

Single-process eventlet/Socket.IO manager topology remains as documented. No new
cross-worker registry, broker, gateway, external auth service or deployment change.
Listener reconnect/supervision/DSN parity remains MOD-024, while its outbound payload
must use the guarded broadcaster now. Before-delivery validation is current at the
check, not an immutable permission lease or cancellation of in-flight network data.

## Client subscription and authoritative refresh

One settled socket subscription per league/token/endpoint generation. Register
handlers before connecting; on every connect emit draft:join for that league and
request current authorized state. Reconnect, manual join, initial load, notify and
successful command completion all feed one refresh controller. Joined UI state and
snapshot callback identity must not tear down/recreate the subscription. Token,
league, account or endpoint change disposes the old controller/socket and starts a
new generation; cleanup removes handlers, cancels pending/in-flight refreshes and
leaves/disconnects once. Callbacks from a disposed generation cannot mutate state.

Treat embedded socket snapshots as refresh signals instead of applying them directly.
Serialize getDraftState requests: at most one in flight, coalesce further signals
into one pending refresh, and fetch again after the current request settles when
needed. Do not let separate summary loaders, action responses or local-storage
restoration bypass that authority for draft state/members/picks/turns. Action errors
remain action errors; a failed privileged command does not revoke ordinary member
read permission. Preserve pick selection persistence and countdown behavior.

An authoritative snapshot with state=null/empty picks must clear corresponding old
values instead of retaining stale state. Abort/ignore obsolete requests on lifecycle
changes and transient disconnect; reconnect rejoins and refreshes. A current snapshot
read denial (401/403/404 after existing bounded auth refresh) or explicit socket access
denial clears the private draft view and subscription readiness and invalidates
in-flight refreshes, so an old successful response cannot repopulate it. A later
authorized join/token generation starts a fresh read. Unexpected transport/
fetch errors show a safe error and retry on a later signal/reconnect, without an
unbounded request loop. Keep apiFetch token-origin/refresh/error semantics from
MOD-019/028A; do not refresh on ordinary permission denial or replay mutations.

Convergence means after reconnect/next valid signal or explicit refresh and settled
reads, authorized clients display the current authoritative snapshot. No guarantee
of replaying missed listener events during an outage, permanent delivery, offline
history, immutable scoring state or total ordering across independently configured
replicas is introduced. MOD-024 owns listener recovery; no durable platform by default.

## Verification and delivery

Failure-first isolated/native tests for every notification branch, no-op/replay and
statement/deferred rollback. Native owned marked PostgreSQL LISTEN proves delivery
only after commit and current snapshots after worker skip/finalize transitions.

Actual Socket.IO test clients with synthetic signed tokens verify connect, join,
reconnect, wrong league/principal, missing/expired token, membership removed after
join and late revocation before delivery. Cover both HTTP/direct and listener paths,
lookup/snapshot errors, safe cleanup and no private payload leakage. No real listener,
worker, configured DB or provider process is launched for verification.

Browser controller tests with controllable socket/HTTP promises reproduce duplicate
and delayed events, reconnect room join, stale action/snapshot responses, token/league
switch, disposal/abort, authoritative empty state and access denial. Exercise actual
subscription/refresh code, not a mirrored fake algorithm. Verify component wiring
uses that controller and one snapshot application path; existing frontend/build and
backend suites remain green. Native prior draft/state/control/ownership contracts
rerun; independent final review; source-hashed evidence and owned cleanup.

No schema migration/dependency, configured app/listener/job/provider run, messaging,
merge/push or deployment. Work in the existing audit checkout and leave uncommitted.
