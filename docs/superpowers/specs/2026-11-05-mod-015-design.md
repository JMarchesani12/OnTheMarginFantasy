# MOD-015 — Seasonal conference membership and consistency

## Confirmed policy

Every draftable team belongs to a conference, including real-world independents.
Use the league/requested season's membership first. Retain current/default
(seasonYear NULL) fallback when that season has no row; ignore other seasons.
No effective mapping means missing configuration, never an independent/uncapped
team. User explicitly rejected the independent-team policy proposed initially.
Do not guess Notre Dame's assigned conference or automatically rewrite mappings.

## Approach

Select one effective membership per team + sport + requested year in SQL. Reuse
one focused, internally parameterized SQL policy where consumers share the exact
semantics; keep resource authorization, query shape, connection ownership and
response projections local. Existing partial unique membership indexes ensure at
most one matching row and one fallback. Never rely on DISTINCT, arbitrary LIMIT,
row iteration order or a dictionary overwrite to resolve conflicting seasons.

Alternative historical exact-year-only lookup would expose missing historical
configuration and abandon current fallback; not selected. Snapshotting/backfilling
all conference history is a separate data/history policy and is not introduced.

## Consumer migration

Begin with schedule team search and roster reads, proving current-only, season-only,
both (same/different conference), other-year-only and no mapping cases. Then migrate
remaining consumers independently: draft snapshot/history, manual/live/timeout cap
checks and conference auto-pick; league conference counts; transaction proposal/
acceptance/application and free-agent counts; conference/member schedules; schedule
ingestion conference-phase routing. Inventory every ConferenceMembership SQL use,
including operational writers/tools, and document intentional non-league consumers.
Existing ingestion season-first logic should be verified/reused, not reimplemented
with different precedence. Scoring formulas/tier/ownership history do not change.

A seasonal move removes the team from its default conference for that requested
year. Counts and cap validation must use that same single selected conference,
including incoming teams and retained rosters, on the caller's transaction. Preserve
existing per-command interpretation of configured cap values; this task changes
membership selection, not unrelated cap semantics. Requested
sport, SportTeam, membership and SportConference must agree; another sport's row or
another year's row cannot provide a cap or eligible draft candidate. A present but
invalid matching-season mapping is a configuration error; do not silently prefer
a default mapping to hide it.

## No independent fallback

Remove the automatic independent bucket and uncapped missing-membership allowance
from draft selection. Manual/live/timeout allocation and ownership-changing commands
reject affected unmapped or cross-sport teams without committing command/history
changes. Auto-pick chooses only mapped conference buckets under existing caps; if
none is eligible, preserve the existing no-pick outcome rather than allocate an
unmapped team. All teams that are mapped to an actual SportConference, whatever its
configured name, follow that conference's cap. Do not manufacture a conference.

Read-only lookup/history/roster retains existing teams and ownership rows even when
mapping is missing, with nullable conference metadata. Remove UI fallback labels
that call such rows Independent: use "Conference unavailable". That display group
is not a draft/cap bucket. Existing explicit conference names remain data labels;
marketing example copy is outside this behavior change. No historical rows are
deleted/retargeted or silently assigned. Preserve read access and ownership rules.

## Consistency and preflight

Audit sport/season relationships in ConferenceMembership and GameResult's
SportSeason/SeasonPhase/team references (and directly relevant phase/conference
links). Add a read-only aggregate preflight and source-backed constraint proposal.
Use selected application write boundaries to reject mismatched sport/season/team/
phase references; retain correct legitimate nullable opponents/phases. Native
fixtures must prove refusal and rollback, including simultaneous field changes.

Any proposed composite FK/unique/check migration must first prove baseline shape,
clean upgrade/replay and atomic dirty-data refusal on owned synthetic PostgreSQL.
Do not change the frozen baseline, install constraints on a configured target,
automatically clean historical rows, or claim direct SQL integrity from query filters.
If constraints require a broader parent/phase decision, deliver the preflight and
explicitly record that rollout dependency instead of inventing policy. No new
infrastructure or global table rename. Application and schema guarantees are distinct.

## Historical and delivery boundaries

Explicit seasonal data is stable against later default moves; historical seasons
without a seasonal row intentionally still follow the default fallback. This is
not a historical snapshot guarantee. Tiers, rule versioning, period remapping and
historical maintenance remain MOD-016. Fair draft-round scaling remains a separate
feature, and membership remains uncapped.

Use the current audit checkout, leave work uncommitted, no application deployment,
configured job/provider run or external messaging. No configured metadata/data
access is implied. Prepare any needed reviewable migration/preflight before asking
for rollout approval; none is authorized by this design.
